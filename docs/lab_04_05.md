# Лабы 4 и 5. Архитектура и тестирование (занятия 5–6)

## Лаба 4. Слои, DI, конфигурация, БД
```
HTTP → routers/ (Handler: разбор запроса, коды ответа)
          │ Depends()                         ← app/deps.py собирает граф зависимостей
          ▼
       services/ (Service: бизнес-правила, транзакция, побочные эффекты через очередь)
          │ получает repo, email_queue, cache в конструкторе
          ▼
       repositories/ (Repository: только SQL/ORM) → PostgreSQL / SQLite
```
- **Handler** не знает про SQL; **Service** не знает про HTTP; **Repository** не знает про бизнес-правила.
- **DI:** `UserService(repo, email_queue, cache, bcrypt_rounds)` — зависимости передаются снаружи; в тестах подменяются на `Mock`.
- **Конфигурация:** `app/config.py` (pydantic-settings) читает env/.env; секреты не в коде; `.env.example` в репозитории, `.env` в `.gitignore`.
  Зачем: один образ для dev/test/prod, секреты не попадают в git, настройка без пересборки.
- **БД:** SQLAlchemy 2.0 ORM; для PostgreSQL — пул соединений (`pool_size=5, max_overflow=10`); схема — SQL-миграции `migrations/*.sql`.
- Побочные эффекты (письмо) вынесены: сервис кладёт сообщение в очередь, отправляет воркер `EmailWorker`.
- Исключения доменного уровня (`NotFoundError`, `ConflictError`…) → единые обработчики в `app/errors.py`; middleware логирует каждый запрос.
