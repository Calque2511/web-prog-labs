# Лабы 9 и 10 (дополнительные). Диагностика, Redis, фоновые задачи (занятия 12–14)

## Лаба 9. Интеграционные тесты и диагностика
- **Request ID** (`app/middleware.py`): берётся из `X-Request-ID` (если формат безопасный, иначе — новый UUID), кладётся в `contextvars`,
  попадает в каждую JSON-строку лога, в тело ошибки и в заголовок ответа; nginx передаёт свой `$request_id`. Это ответ на «найти все логи по request_id».
- **Структурированные логи:** `{"ts","level","logger","request_id","message","context"}`, время `ts` в UTC; метод, путь, статус, время выполнения, IP — в логе запроса.
  Пароли/токены не логируются.
- **Интеграционные тесты** (`tests/test_integration_postgres.py`): настоящий `UserRepository` + PostgreSQL, схема из SQL-миграций, `TRUNCATE` после каждого теста
  (независимость), проверка БД и побочных эффектов (письма, каскад `ON DELETE CASCADE`), а не только HTTP-статуса.
  Окружение: встроенный `pgserver` либо `docker-compose.test.yml` + `TEST_DATABASE_URL`.
- **Регрессионные тесты** (`tests/test_regression.py`): скидка, регистронезависимая уникальность email и найденный в ходе работы баг —
  500-ответ терял `X-Request-ID` и не попадал в метрики (исправлено в `middleware.py`).
- **Метрики Prometheus** `GET /metrics`: `http_requests_total{method,endpoint,status}` (endpoint — шаблон маршрута, а не URL → нет взрыва кардинальности),
  `http_request_duration_seconds`, `http_errors_total`. Алерт-правила: [`prometheus/alerts.yml`](../prometheus/alerts.yml).
- `GET /health` проверяет БД и Redis.

## Лаба 10. Redis и фоновые задачи
- **Cache-aside** (`UserCache`): `GET /users/{id}` → Redis `user:{id}` с TTL 60 с; изменение и удаление инвалидируют ключ (тесты: попадания/промахи, TTL, инвалидация).
- **Очередь** (`EmailQueue`, Redis list) и **воркер** (`EmailWorker`): создание пользователя кладёт письмо в очередь, воркер запускается после ответа (`BackgroundTasks`).
- **Идемпотентность:** `SET processed:{message_id} NX` — повторно доставленное сообщение не отправляется дважды;
  при сбое отправки отметка снимается, сообщение возвращается в очередь (тесты `test_worker_*`).
- Для продакшена вместо `BackgroundTasks` — отдельный процесс-воркер; для надёжной доставки — RabbitMQ/Redis Streams с подтверждениями.

> По умолчанию тесты используют `fakeredis`; весь набор (109 тестов) также прошёл на настоящем Redis (`REDIS_URL=redis://localhost:6380/0`).
> В запущенном compose Prometheus собирает `/metrics` приложения (target `webprog`: up), правила из `prometheus/alerts.yml` загружены. Grafana запускается, дашборды не настраивались.
